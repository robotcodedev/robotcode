# Proposal: doc-cli

## Why

Robot Framework's Libdoc has no uniform text form of library documentation. `libdoc <Lib> show` prints the documentation as the library wrote it: on RF 5.0–7.4 raw Robot Framework markup wrapped at 78 characters, on RF 7.5 Markdown that is valid only when the library itself is documented in Markdown (Libdoc's `LibdocMarkdownWriter` says so; `%TOC%` stays literal and introduction sections come out as `#` headings next to the library title). `robotcode libdoc` passes this through unchanged.

RobotCode already converts every documentation format to Markdown on every supported Robot Framework version, but only for single keywords and library introductions (hover, REPL `.kw`, `robot-debug`). Its only full-library rendering, `LibraryDoc.to_markdown(only_doc=False)` used by the REPL's `.doc`, is not fit to be read, searched or published: the heading hierarchy is broken (`## Library *Collections*`, `### Introduction`, introduction sections back at `##`, `### Keywords` with every keyword at `##` followed by repeated `### Arguments:` / `### Documentation:`), the keyword order changes from run to run (it follows the library's keyword collection, which for `Collections` depends on `PYTHONHASHSEED`), data types are missing (a `TODO` in `_get_toc_sections`), a `|` inside a Robot-format table cell breaks the table (BuiltIn `Should Match Regexp`, String `Replace String Using Regexp` on RF 6.1), and link targets carry `\#` escapes (328 of them in BuiltIn on RF 6.1). There is no RobotCode command to read, search or export library documentation outside a REPL session, although users, website generators and AI agents all need one.

## What Changes

- **Canonical library documentation Markdown.** One documented structure for the documentation of a library or resource file, identical on RF 5.0–7.5 and for every documentation format: `# <Name>` with a metadata list (type, version, scope, source, import arguments), `## Introduction` with its sections one level below, `## Importing`, `## Keywords` with one `### <Keyword>` per keyword in Libdoc's order, `## Data types`. Per keyword: every argument once with kind, types, default and description, return value, raised exceptions, tags, then the documentation — as labelled blocks, not as headings. `%TOC%` becomes a table of contents, references to keywords, sections and types become links, every heading has a stable anchor, and the renderer returns a navigation outline next to the Markdown. Private keywords are left out, as in Libdoc's HTML.
- **Converter corrections for all surfaces.** In the shared Robot-format converter, `|` inside table cells is escaped and the targets of converted links (`[url|text]` and bare URLs) lose the `\#` escape. This also changes hover, REPL and tree-view output for such documentation (modifies `keyword-documentation-rendering`); everything else there stays as it is. Of the 328 escaped link targets in BuiltIn on RF 6.1, 9 come from the converter; the other 319 are the backtick auto-links that `LibraryDoc._link_inline_links` adds to the old full-library rendering, which the canonical renderer does not use and which stay as they are. The library scope is stored as Libdoc names it (`GLOBAL`; RobotCode stores `Scope.GLOBAL` on RF ≥ 7.0 today), which the library hover shows as well.
- **New command** `robotcode doc TARGET...` (the name is a placeholder, see design Q2): explicit targets only — library names, library paths, `Name::arg1::arg2` like Libdoc, resource and suite files — several per call, resolved through an `ImportsManager` built from `robot.toml` so the command shows what the analysis sees (profiles, variables, python path, `load-library-timeout`, cache settings, the analysis disk cache).
- **Output.** On an interactive terminal a documentation browser (TUI) modeled on Libdoc's HTML page: a sidebar with the introduction and its sections, Importing, Keywords with count and filter, Data types and Tags, next to RobotCode's existing documentation viewer (search, links, back/forward). Otherwise the canonical Markdown through the usual CLI output path (rendered on a coloured terminal, raw in pipes, with `--no-color` and in AI-agent sessions). `-o FILE` writes one file, `-o DIR/` one file per document with links between them.
- **Lookup options.** `-k/--keyword PATTERN` shows single keywords (like `libdoc … show`), `--list` lists keyword names with their first documentation paragraph, `--search`/`--search-regex` search names, documentation, arguments and tags across all given targets with the semantics of `results`/`discover`.
- **Agent skill.** The `robotcode` skill in robotframework-agent-plugins routes documentation lookup to the new command (keeping `robotcode libdoc` as fallback); the vendored copy in `chat-plugins/` is re-synced.
- **Docs.** A user guide page for the command; the CLI reference is regenerated.
- **Open** (design.md, Open Questions, each with a recommended default): the anchor scheme, the command name, the hosting package (the TUI needs `prompt_toolkit`, which only `robotcode-repl` has), whether the REPL's `.doc` switches to the new browser and the hover keeps its compact rendering (recommended: yes to both), Libdoc spec files as input, JSON output, a repeatable `--arg` option, and the AI-agents docs page.
- **Not in this change:** listing installed or project libraries (`library-index`), the VS Code documentation browser (`vscode-doc-browser`), variable files as targets, any change to `robotcode libdoc`.

Depends on `analyze-config-in-robot`. That change moves the analysis part of the `[tool.robotcode-analyze]` model (the base class `AnalyzeConfig`) from `robotcode-analyze` to `robotcode-robot` (`robotcode.robot.config.analyze_config`), makes the section a built-in section of `robotcode-robot`'s configuration loader, and adds `get_analyze_config` and the shared `-v/-V/-P` merging `merge_variable_and_path_options` (`robotcode.robot.config.utils`). The command loads the configuration without `extra_tools`, reads the section with `get_analyze_config`, merges its `-v/-V/-P` options with `merge_variable_and_path_options` and builds its `ImportsManager` through `robotcode-robot`, so it neither uses nor depends on `robotcode-analyze`. Independent of `library-loading-robustness` and `library-keyword-set-declaration`: with them, libraries whose keywords depend on their import arguments are shown correctly and a fallback load is marked, but the command works without them. `vscode-doc-browser` and `library-index` build on this change.

## Capabilities

### New Capabilities

- `library-documentation-markdown`: The canonical Markdown form of a library's or resource file's documentation — structure, keyword and type entries, ordering, conversion of all documentation formats, table of contents, links, anchors, the navigation outline and load errors — used by the documentation command, its browser and later the VS Code browser.
- `documentation-cli`: The documentation command — explicit targets, resolution through the project configuration, output modes (browser, Markdown, file, directory), keyword selection, listing, search, errors and exit codes, and the terminal documentation browser.

### Modified Capabilities

- `keyword-documentation-rendering`: the guarantee that non-Markdown keywords without argument descriptions render "exactly as before" gets two exceptions — `|` in Robot-format table cells is escaped and link targets contain no `\#` — and a new requirement states both corrections.

- New `packages/robot/src/robotcode/robot/diagnostics/documentation_markdown.py`: canonical renderer, outline, short documentation.
- `packages/robot/src/robotcode/robot/diagnostics/library_doc.py`: `get_library_doc_from_library` stores the scope name on RF ≥ 7.0; `_link_inline_links`/`_create_toc` use the shared slug helper (Q1).
- `packages/robot/src/robotcode/robot/utils/markdown_docs.py`: the slug helper follows the anchor scheme of Q1 (one stateful slugger for duplicates) and a resolver for Robot-format backtick names; `packages/robot/src/robotcode/robot/utils/markdownformatter.py`: escaped pipes in table cells, no `\#` in link targets.
- The command (`doc_cli.py` + hook registration) in the package chosen in Q3 (recommended: `packages/repl/src/robotcode/repl/`, with no new dependency); builds the `ImportsManager` directly from `robotcode-robot` and `robotcode-core` (`Workspace`, `DocumentsCacheHelper`, `get_analyze_config` from `robotcode.robot.config.analyze_config`, `merge_variable_and_path_options` from `robotcode.robot.config.utils`, both provided by `analyze-config-in-robot`) and analyses nothing; reuses `robotcode.runner.cli._search.make_search_matcher` and `app.echo_as_markdown`.

- Docs: new `docs/03_reference/browsing-documentation.md` ("Browsing Library Documentation"), `docs/03_reference/index.md`, the package overview in `docs/03_reference/cli.md`, the generated part of `cli.md` (`hatch run create-cmd-line-docs`); `docs/03_reference/repl.md` if Q4 is confirmed.
