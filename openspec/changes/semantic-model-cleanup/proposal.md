# Proposal: semantic-model-cleanup

## Why

Phase 4 of the SemanticModel migration (`dev-docs/semantic-model.md`) is the final cleanup: once the SemanticModel is the default and every LSP feature answers the same on it (Phase 3, `semantic-model-switchover`), the parallel legacy machinery is pure dead weight and a maintenance hazard (every fix must be mirrored into both analyzers). This change deletes it: the legacy fallback paths in the LSP features, `KeywordTokenAnalyzer` (the legacy semantic-tokens engine), the feature flag, and the three retired subsystems — `NamespaceAnalyzer` (~2400 lines, [namespace_analyzer.py](../../../packages/robot/src/robotcode/robot/diagnostics/namespace_analyzer.py)), `ModelHelper` (~780 lines, [model_helper.py](../../../packages/robot/src/robotcode/robot/diagnostics/model_helper.py)), and `ScopeTree` (~230 lines, [scope_tree.py](../../../packages/robot/src/robotcode/robot/diagnostics/scope_tree.py)).

The `Namespace` scope API (`find_variable`, `get_variable_matchers`, `get_resolvable_variables`, [namespace.py:357-377](../../../packages/robot/src/robotcode/robot/diagnostics/namespace.py)) still delegates to `self._scope_tree`, which the `SemanticAnalyzer` builds as well, and completion and hover read variables through it. It must be redirected to the `SemanticModel` before `ScopeTree` can be deleted, and the model's `get_variables_at()` does not match it yet: it compares lines only and reverses the precedence of the file's variables (a built-in variable overrides an own one of the same name).

## What Changes

- **Remove legacy fallback paths** from the migrated LSP features (the `else` branches that ran `ModelHelper`/AST when the flag was off): semantic tokens (with `KeywordTokenAnalyzer`), inlay hints, signature help, all code actions, selection range, inline value, debugging utils. Each becomes model-only. Hover and completion have no fallback to remove: hover reads the reference lists (`semantic-model-hover`, design D1), completion the namespace and the current text (`semantic-model-completion`, design D1); the `ModelHelper` methods completion calls move into completion.
- **Remove the feature flag** — the model is unconditional: `robotcode.experimental.semanticModel` (`package.json`, `workspace_config.py`), the IntelliJ setting, the `semantic-model` option of robot.toml (a robot.toml that still sets it loads, the option is ignored), the switch-off rule in `document_cache_helper.py`, `set_semantic_model_enabled`, the flag in the namespace cache metadata and in `dump-model`.
- **Redirect the `Namespace` scope API** to the model: first `SemanticModel.get_variables_at()` gets the column-aware visibility and the precedence of `ScopeTree` (local, command line, own, imported, built-in), and a test compares `ScopeTree` and the model over the LSP test data; then `find_variable` → `model.find_variable`, `get_variable_matchers` / `get_resolvable_variables` → `model.get_variables_at` (with resolution). The `SemanticAnalyzer` stops building a `ScopeTree`; `AnalyzerResult.scope_tree` and the `local_scopes` field of `NamespaceData` go (the pickled model already carries `DefinitionBlock.local_variables`).
- **Delete** `namespace_analyzer.py`, `model_helper.py`, `scope_tree.py`.
- **Remove the comparison tests**: Level-E (the old analyzer they compared against is gone) and the comparisons of the model path with the legacy path (`test_semantic_tokens_flag_parity.py`, `test_hover_model.py`, `test_completion_model.py`, the parity checks of the other `test_*_model.py` suites); what checks expected results of its own stays as a single-path test, and the regtest snapshot suites stay the reference. **Simplify Level-D** (drop the flag parameterization — there is only one path).
- **Main specs**: every main spec that pins both analysis paths or the flag gets a REMOVED or MODIFIED delta, written when the change is implemented (see Capabilities).
- **Reorganize the design doc**: with the migration finished, extract the data-structure/API reference from `dev-docs/semantic-model.md` into a code-adjacent `semantic_analyzer/README.md` (the living reference of the shipped model), trim the now-historical migration narrative to a short design rationale (or remove it — git history and archived changes preserve the "why"), and move any remaining un-proposed ideas to a backlog.

## Capabilities

### New Capabilities

- `semantic-model-sole-implementation`: The SemanticModel/`SemanticAnalyzer` is the only analysis and query path — legacy fallbacks, the feature flag, `NamespaceAnalyzer`, `ModelHelper`, `KeywordTokenAnalyzer` and `ScopeTree` are removed, and the `Namespace` scope API delegates to the model.

### Modified Capabilities

The main specs that pin both analysis paths, the legacy path or the flag. Their deltas (REMOVED where a requirement only compares the two paths, MODIFIED where it states behavior on both paths or with and without the flag) are written when the change is implemented, once `semantic-model-switchover`, `semantic-model-completion` and `semantic-model-feature-tests` are archived; written now, a MODIFIED block would overwrite later changes of these specs at archive time. Known today:

- `semantic-model-tier1-parity`, `semantic-model-hover`, `semantic-model-sidecar-consumers`, `semantic-model-inspection`, `semantic-highlighting`, `variable-assignments`, `variable-name-resolution`, `private-keywords`, `vscode-documentation-viewer`;
- after their archive: `semantic-model-default`, `semantic-model-variable-modifiers`, `semantic-model-completion`;
- from `semantic-model-feature-tests`: the "Differences from the legacy path" requirements of `inlay-hints`, `signature-help`, `code-action-quick-fixes`, `code-action-refactorings` and `semantic-highlighting` are REMOVED, together with the tests of their scenarios.

## Impact

- **Code**: deletes `packages/robot/.../namespace_analyzer.py`, `model_helper.py`, `scope_tree.py` and `KeywordTokenAnalyzer` with the legacy semantic-tokens path; edits `namespace.py` (scope API + `NamespaceData`), `analyzer_result.py`, `semantic_analyzer/analyzer.py` (no `ScopeTreeBuilder`) and `semantic_analyzer/model.py` (`get_variables_at()`), `document_cache_helper.py`, `workspace_config.py`, `package.json`, the IntelliJ settings, `packages/analyze/.../config.py` and `dump_model.py`; moves completion's helpers into `completion.py`; removes the `else` fallback in every migrated LSP feature part.
- **Tests**: remove Level-E (`test_variable_pipeline_comparison.py`, `test_analyzer_performance.py`, `test_nested_variable_resolution.py`'s parity halves) and the comparisons with the legacy path; flag-parametrized tests run once; simplify Level-D (remove flag parameterization); a temporary comparison of `ScopeTree` and the model guards the scope API migration.
- **Docs**: the regenerated `etc/robot.toml.json`, `reference/config.md` and `reference/vscode-settings.md`; extract the data-structure/API reference from `dev-docs/semantic-model.md` into a code-adjacent `semantic_analyzer/README.md` (living reference of the shipped model); trim the historical migration narrative to a short rationale or remove it; mark the feature-flag / transition-period passages historical. Phase-4 completion is tracked in OpenSpec.
- **Dependency (HARD GATE)**: MUST come after `semantic-model-switchover`, `semantic-model-completion` and `semantic-model-feature-tests` are archived (the tests of the last replace the comparisons this change deletes) and the switchover is stable (flag default `true`, no reported regressions). This is the second of only two hard gates: deleting `NamespaceAnalyzer`/`ModelHelper`/`ScopeTree` and the fallbacks is only safe once nothing reaches them. This is the point of no return — after deletion the legacy path cannot be re-enabled by config; rollback is git revert only. Not breaking for users who keep the default; whoever switched the model off gets it now, and the setting is ignored. Breaking for any out-of-tree code importing `NamespaceAnalyzer`/`ModelHelper`/`ScopeTree`.
