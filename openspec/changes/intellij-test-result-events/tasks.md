## 3. Converter

- [ ] 3.1 Add a subclass of `KillableColoredProcessHandler` with constructors from a command line and from a started process (or extend it, if the graceful-stop work already added one) whose `createOutputDataReader()` and `createErrorDataReader()` return `BaseOutputReader` subclasses that deliver text through `notifyTextAvailable` with the stdout or stderr key, count completed read cycles in `beforeSleeping()`, and can be woken through their sleep monitor. Add a fence that wakes both readers and waits, bounded, until each has completed a cycle that began after the call, and returns at once when the process has ended. Let the run state create this handler where it creates its handler: in `startProcess()` today, or in `createProcessHandler(...)` if the run state is already a `PythonCommandLineState`. Verify with JUnit 4 tests of the fence against fake readers: text pending in a fake reader is delivered before the fence returns; the fence returns after the timeout when a reader never completes a cycle; it returns at once after the process ended.
- [ ] 3.2 Rewrite `RobotOutputToGeneralTestEventsConverter` to call the processor from `getProcessor()` directly with the event classes, the robot event ids as node and parent ids, and the location URLs, names, durations and messages of today; to apply every call under one lock; to queue DAP items until `startTesting()` and drop them after `finishTesting()`; to pass every DAP item through the fence before it is applied; to override `process()` so that process text becomes uncaptured output as it arrives, without the line splitter; and to end its DAP subscriptions in `dispose()`. Remove the service messages, the captured visitor, the `afterInitialize` wait and the single-thread context. Verify with light platform tests (as `MyPluginTest`) against a recording `GeneralTestEventsProcessor`: suite and test start and end with `PASS`, `FAIL` and `SKIP` produce the expected calls in order with ids, parent ids, location URLs and durations; items before `startTesting()` are applied after it in their order; items after `finishTesting()` produce no call; process text without a newline arrives as uncaptured output at once; after `dispose()`, a robot event produces no call.
