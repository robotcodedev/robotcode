An agent does what you ask, the way you ask it. A question gets you an answer, and an instruction gets you a change, including every decision you left open. This tutorial shows how to ask and instruct an agent on a Robot Framework project, in the order in which you get to know a project and work on it.

Each step starts from something you want to find out or get done. You send the agent a prompt, read its answer, and learn what to look for and what to do next. The commands come from the agent: when you want to know how it found something out, you ask, and so you get to know RobotCode's command line along the way. What happens behind a request is on [How the Skill Works](/guides/ai-agents/how-the-skill-works/).

## Following along

Use your own project, or the example project in [`robotcodedev/webshop-ai-example`](https://github.com/robotcodedev/webshop-ai-example): a small web shop whose tests use an in-memory Python library, `libraries/ShopLibrary.py`, through the keywords in `resources/`. Its README says how to set it up. Then start the agent you set up on [Setting Up](/guides/ai-agents/setting-up/) in that folder.

Some things in the example are wrong on purpose, because the steps find them.

Each step starts from the project as it is in the repository, not from what an earlier step changed. The agent changes files along the way, so to start over, reset the repository.

## The answers on these pages

The answers shown are from real runs in the example project, as the agent wrote them. Between a prompt and its answer, you see the `robotcode` commands the agent ran for it, each linked to its documentation, without their output and without what the shell does around them. The agent also reads files and runs other commands, which aren't shown. `…` marks a part that was left out. Your agent words its answers differently, and it may take other steps, even the same agent on another day. What a step says to look for applies either way.

Agents differ in how they keep a REPL or a debugger running between your prompts: some type into the running command, others use [`robotcode session`](/guides/cli/sessions/). You don't have to do anything about that.

With a smaller, faster model such as Haiku, start your first prompt with *Use the robotcode skill.* Such a model doesn't always load the skill by itself.
