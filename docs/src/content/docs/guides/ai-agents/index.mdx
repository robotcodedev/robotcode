AI coding agents are good at writing code and bad at guessing how *your* Robot Framework project is actually wired. Reading the `.robot` files doesn't reliably tell which files become suites, which tags a test really ends up with, where a keyword comes from or what a finished run contained. All of this is decided at runtime by `robot.toml`, profiles, variables, the installed library versions, and pre-run modifiers.

**RobotCode** closes that gap with a plugin for AI agents. The plugin contains a skill, a set of instructions that the agent loads when a request looks like Robot Framework work. The skill teaches the agent to work through the project's own [`robotcode`](/reference/cli/) command line instead of guessing, so that the agent sees your tests, keywords and results the way Robot Framework resolves them, with the profiles of your project's `robot.toml`. This works for tests and RPA tasks alike.

## Agents

The plugin comes with the VS Code extension for **GitHub Copilot Chat** and is on by default. **Claude Code**, **GitHub Copilot CLI** and **Codex** install it from a marketplace, in PyCharm as well, because RobotCode's PyCharm plugin doesn't include it yet. Other agents that support the [Agent Plugins](https://agent-plugins.org/) standard can load it too.

## Getting started

1. **[Set up the agent](/guides/ai-agents/setting-up/):** in VS Code, the extension brings the plugin and `robotcode`. For other agents, install the plugin from the marketplace and RobotCode's command line tools in the project's Python environment.
2. **[Brief the agent](/guides/ai-agents/briefing/):** write down once what the agent cannot find out from the project itself, such as the system under test and your conventions.
3. **Ask:** describe your task. The agent picks the `robotcode` command for it, and [the tutorial](#the-tutorial) shows how to ask.

## The tutorial

[Working with the Agent](/guides/ai-agents/working-with-the-agent/) is a tutorial in seven steps. You work through them with your own project or the example project, and with the agent you use:

1. **[Getting to know the project](/guides/ai-agents/working-with-the-agent/getting-to-know-the-project/):** asking what a project tests, which tests cover a requirement and what a keyword takes, and trying a keyword.
2. **[Writing a test from a requirement](/guides/ai-agents/working-with-the-agent/writing-a-test/):** having the agent learn a library and try keywords in a REPL, write the test, check and run it, and asking how you know that it works.
3. **[Running what you need](/guides/ai-agents/working-with-the-agent/running-what-you-need/):** saying what to run, checking what the run really reached, and keeping the results you still need.
4. **[Finding out why a test failed](/guides/ai-agents/working-with-the-agent/finding-out-why-a-test-failed/):** asking what happened and whether it happens every time, deciding what is right, and only then asking for the fix and its proof.
5. **[Debugging step by step](/guides/ai-agents/working-with-the-agent/debugging-step-by-step/):** stopping a real test and steering it prompt by prompt.
6. **[Checking before a push](/guides/ai-agents/working-with-the-agent/checking-before-a-push/):** asking for a check, also with the CI profile, deciding what gets fixed, and marking what is intended.
7. **[A profile for the CI server](/guides/ai-agents/working-with-the-agent/a-profile-for-the-ci-server/):** saying what the server needs, and checking the resulting profile before the first run.
