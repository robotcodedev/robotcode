AI coding agents are good at writing code and bad at guessing how *your* Robot Framework project is actually wired. Which files become suites, which tags a test really ends up with, where a keyword comes from, what a finished run contained — none of that is reliably visible by reading `.robot` files. It is decided at runtime by `robot.toml`, profiles, variables, the installed library versions, and pre-run modifiers.

**RobotCode** closes that gap with a plugin for AI agents. Its skill teaches the agent to work through the project's own [`robotcode`](/reference/cli/) command line instead of guessing, so that the agent sees your tests, keywords and results the way Robot Framework resolves them, with the profiles of your project's `robot.toml`. This works for tests and RPA tasks alike.

## Agents

The plugin comes with the VS Code extension for **GitHub Copilot Chat** and is on by default. **Claude Code**, **GitHub Copilot CLI**, **Codex** and other [Open Plugins](https://open-plugins.com/) agents install it from a marketplace. The usual agents work in PyCharm as well; RobotCode's PyCharm plugin does not bring the plugin for them yet, so you install it from the marketplace there too.

## Getting started

1. **[Set up the agent](/guides/ai-agents/setting-up/):** turn the plugin on in VS Code or install it from the marketplace, and install RobotCode's command line tools in the project's Python environment.
2. **[Brief the agent](/guides/ai-agents/briefing/):** write down once what the agent cannot find out from the project itself, such as the system under test and your conventions.
3. **[Ask](/guides/ai-agents/working-with-the-agent/):** describe your task. The agent picks the `robotcode` command for it.

## The tutorial

[Working with the Agent](/guides/ai-agents/working-with-the-agent/) is a tutorial in seven steps. You work through them with your own project and the agent you use:

1. **[Getting to know the project](/guides/ai-agents/working-with-the-agent/getting-to-know-the-project/):** which tests, tags and suites there are, which tests cover a requirement, and what a keyword takes.
2. **[Writing a test from a requirement](/guides/ai-agents/working-with-the-agent/writing-a-test/):** learning a library, trying keywords in the REPL, then checking and running the test.
3. **[Running what you need](/guides/ai-agents/working-with-the-agent/running-what-you-need/):** a tag, a suite or one test, with a profile.
4. **[Finding out why a test failed](/guides/ai-agents/working-with-the-agent/finding-out-why-a-test-failed/):** reading the results of a run and comparing runs.
5. **[Debugging step by step](/guides/ai-agents/working-with-the-agent/debugging-step-by-step/):** stopping a real test and steering it prompt by prompt.
6. **[Checking before a push](/guides/ai-agents/working-with-the-agent/checking-before-a-push/):** analyzing the code without running it, also with the CI profile.
7. **[A profile for the CI server](/guides/ai-agents/working-with-the-agent/a-profile-for-the-ci-server/):** writing a profile in `robot.toml` and checking it.
