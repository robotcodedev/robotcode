The **Test Explorer** is VS Code's **Testing** view; open it with the flask icon in the activity bar. RobotCode lists the suites, tests and tasks of every workspace folder there, as "Robot Framework Tests/Tasks", and runs or debugs them. To run and debug from the editor, see [Running and Debugging](/guides/vscode/running-and-debugging/).

## Where the tests come from

RobotCode finds the tests the way [`robotcode discover`](/guides/discovering-tests/) does, in each workspace folder: with the paths, profiles and other options of the folder's `robot.toml`, and without the files that [`.robotignore`](/guides/ignoring-files/) excludes. The tree follows Robot Framework's suite structure: the workspace folder, the suites made from directories and files, and the tests and tasks in them.

The tree updates when you change, save, create or delete a Robot Framework file, and when you create, copy, rename, move or delete a folder; it also takes unsaved changes into account. Files and folders that are created, copied, renamed, moved or deleted outside VS Code, for example by `git` or in a terminal, update the tree as well. A change to a `robot.toml`, `.robot.toml`, `pyproject.toml`, `.robotignore` or `.gitignore` in the workspace folder restarts the folder's language server and updates the tree too. After other changes, for example to a `robot.toml` outside the workspace folder, **Refresh Tests** in the view's title bar reads the tests again.

## Running and debugging

Hover over a suite, test or task to run or debug it with the buttons beside it; **Run Tests** and **Debug Tests** in the view's title bar run all of them. A run shows its result at each entry: passed, failed or skipped, with the time it took. For a failed test, the message appears in the editor at the line that failed, also as a peek with the whole message. **Show Output** in the title bar opens the output of the run, with the messages Robot Framework logged.

## Run profiles

A run uses a run profile. RobotCode creates these:

- **Run** and **Debug** for each workspace folder, with the folder's name added in a workspace with several folders. They run with the configuration profiles you selected with **RobotCode: Select Configuration Profiles**; **Configure Test Profiles** in VS Code opens that command for them.
- A **Run** and a **Debug** profile for each profile of the folder's `robot.toml`, named after the profile and its description, such as "Run ci - Staging shop".
- A **Run** and a **Debug** profile for each configuration in `launch.json` with the purpose `test-profile`, named after the configuration.

The arrow beside **Run Tests** and **Debug Tests** lists the profiles to run with and offers **Select Default Profile**, which decides the profile a click on the button uses. **Execute Using Profile...** in the context menu of an entry runs it once with another profile.

<ThemeImage
  name="test-explorer-profiles"
  alt="VS Code's choice of the default run profile lists Run, Run ci - Staging shop and Run dev - Local shop in Firefox."

A test profile in `launch.json` combines the settings of a launch configuration; the snippet **RobotCode: Test Profile** creates one. For example, this profile runs the selected tests with the `ci` profile of `robot.toml`, and only those tagged `smoke`:

```json title=".vscode/launch.json"
{
  "name": "Smoke on staging",
  "type": "robotcode",
  "request": "launch",
  "purpose": "test-profile",
  "presentation": { "hidden": true },
  "profiles": ["ci"],
  "include": ["smoke"]
}
```

## Filtering

The filter field above the tree takes text and `!text` to exclude, and tags with `@`: the tags of your tests are offered as `@robotCode.RobotFramework:<tag>`. VS Code adds filters such as `@failed`, `@executed` and `@openedFiles`, and the funnel button beside the field.

## Problems while finding the tests

When Robot Framework reports a problem while RobotCode reads the tests, the problem appears in the **Problems** view at the file, with the source `robotcode.discover`, for example "'Test Cases' section is not allowed in suite initialization file." or "One file cannot have both tests and tasks." Until you fix it, the suite of that file, or its tests, may be missing from the tree.

When RobotCode finds no tests or tasks at all and reports no problem, the Testing view shows a hint from RobotCode below VS Code's own text: where tests are looked for, with **Refresh Tests** and a link to the [troubleshooting page](/guides/vscode/troubleshooting/). Without a Python environment with Robot Framework, the hint says so instead and offers **Select Python Environment**.

## Switching the Test Explorer off

The setting [`robotcode.testExplorer.enabled`](/reference/vscode-settings/#robotcode.testExplorer.enabled) switches the Test Explorer integration off, also for single workspace folders. While it is off for every workspace folder, the Testing view says so and offers to open the setting.
